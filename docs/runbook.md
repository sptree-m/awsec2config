# 導入・監査・運用・復元

## 導入前

対象を確認し、検証 EC2 と復旧経路を用意します。再起動の時間を調整し、OS 権限、空き容量、既存監視、組織ポリシーを確認します。

Ubuntu は journald / rsyslog を再起動します。augenrules --load は全ディスクルールを再ロードするため、他管理者の未反映ルールがないことを確認します。immutable（enabled 2）は停止します。専用ファイルを上書きしません。

Windows の GPO は設定を上書きできます。GPO 管理の設定は正管理者へ依頼します。ログモードは元の値を維持するため、容量到達時の循環／停止／保存を担当者が確認します。

## 受け入れ確認

1. Apply と Audit で状態記録、設定値、サービス、有効 audit ルール、lost を確認。FAIL／UNKNOWN の理由と対応を記録。
2. Ubuntu の logger マーカーを auth で照合。ローテート後は UNKNOWN になるので新規マーカーを生成し journal／auth の証拠を添付。
3. 検証 Windows のテストアカウントで4624／4625、新規 PowerShell で4104を確認。連続失敗によるロックアウトを避ける。Firewall 拒否・アカウント変更等は担当者の試験手順で検証。
4. Ubuntu は承認されたファイル変更で専用キーと日時を確認。sshd_config.d/、sudoers.d/、全コマンドはこのベースラインの対象外。追加ルールは正管理者が設計。
5. 各中央送信先で同じイベントを照合し AWS 監査を実行。CloudTrail selectors・配信日時・エラー・リージョンを確認。
6. Restore のプレビュー・実行、元の値との一致、証拠保持を確認。他管理者の変更を入れ競合停止も確認。

実機確認まで本番で動作確認済みとは扱いません。Windows CSV・ローカライズ・GPO、Ubuntu 既存ルールとの相互作用を確認してください。

## 日々の運用

Daily は読取処理です。出力先は毎回新しくします。必要なら cron / systemd timer / タスクスケジューラに登録し、担当者が実行権限と終了コード2の扱いを管理します。自動通知・アカウント停止はしません。

- ログオン失敗増加、失敗後の成功、送信元、特権、未知アカウント／グループ、PowerShell コマンド。
- Windows 1102／4719、Ubuntu audit lost、サービス停止、設定差分。
- 空き容量、ローテート、Agent、配送途絶、CloudTrail エラー。
- 継続する UNKNOWN の調査。読み取り不可を異常なしにしない。

EVTX は期間内全件で大量になり得ます。journal は60秒のタイムアウトで失敗は UNKNOWN。audit/auth 末尾と Firewall ファイルは補助証拠で、ローテート済みログや全期間を網羅しません。調査時は中央ログと元ログも取得します。

不審アクセスは担当へ報告し証拠保全します。レポートを公開リポジトリに保存しません。出力は OS 管理者に制限しますが、親フォルダーとコピー先の ACL も確認します。

## 復元

1. 状態を保全し他管理者の変更を確認。手動 Agent は先に元の設定・稼働状態へ復元。
2. Restore でプレビュー。
3. --execute / -Execute で実行。
4. 元の値・サービス・証拠保持を確認。

Ubuntu は専用ファイルと専用 runtime watch のみ解除し auditctl -D は行いません。ログ、永続 journal、状態、空の親ディレクトリは保持します。

Windows は監査ポリシー完全バックアップを戻すため、現在の全ポリシー／バックアップが導入前か導入直後と一致しなければ停止します。元のログサイズ等へ戻し追加したレジストリ値だけ削除、空キーは保持します。途中失敗の部分的 auditpol 変更も不一致なら停止し、正管理者が audit-before.csv と差分を確認して手動復旧します。

競合で強制上書きや状態削除をしません。状態は信頼できる管理者が保護する前提で root／管理者による改ざん検出は保証しません。AWS リソースは削除しません。

Ubuntu の audit ログ容量／世代は既存 auditd.conf の運用を維持します。Firewall ログは Windows では最大32767KiBの循環ファイルで、許可ログも記録するため高トラフィック環境では短期間で上書きされ得ます。長期保管は中央ログで確認します。Ubuntu Firewall の拒否ログ有効化、EDR、全コマンド監査は本キットの自動設定対象外です。
